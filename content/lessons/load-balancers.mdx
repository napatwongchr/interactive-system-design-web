Your app has 100,000 users. You've cached aggressively, indexed your queries, and moved work to background jobs. Your server is still at 90% CPU under peak load.

One server isn't enough anymore.

You spin up three more. Same code, different machines. But now there's a question: when a user visits your app, which server do they talk to?

That's what a load balancer answers.

## The Single Entry Point

A **load balancer** sits in front of your servers. Every request goes to the load balancer first. It picks a server and forwards the request. To the user, it looks like one URL, one service.

## How It Decides Where to Send Requests

**Round-robin** — request 1 goes to Server 1, request 2 to Server 2, request 3 to Server 3, then back to Server 1. Dead simple and often good enough.

**Least connections** — send to whichever server has the fewest active connections right now. Better when some requests take longer than others.

**IP hash** — always send the same client to the same server based on their IP address. Only needed if your servers have local state (but you'll avoid that — more on this in the Stateless Servers lesson).

## Health Checks

The load balancer constantly checks if your servers are alive, usually by hitting `/health` every few seconds. If a server stops responding, the load balancer stops sending it traffic.

When the server recovers, traffic resumes.

This is how you deploy with **zero downtime**: take Server 1 out of rotation → update it → put it back → repeat for Server 2 → repeat for Server 3. Users never see a blip.

## Layer 4 vs Layer 7

There are two kinds of load balancers:

**Layer 4** (TCP) — routes based on IP address and port. Ultra-fast. Can't look at the request content.

**Layer 7** (HTTP) — can read the HTTP request: the URL, headers, cookies. Much more powerful. Can route `/api/*` to your API servers and `/` to your frontend servers. Can terminate SSL. Can inject headers.

Almost every production app uses Layer 7. AWS ALB, Nginx, Caddy, and Vercel's infrastructure are all Layer 7 load balancers.

## You Already Have One

If you're on Vercel or similar platforms, there's already a load balancer in front of your app. You never configured it — it's just there.

When you scale beyond one managed server, you'll explicitly configure one. But the concept is the same as what you're already using.
