Your server is in Virginia. A user in Tokyo opens your app.

Every image, every JavaScript bundle, every CSS file has to travel from Virginia to Tokyo before they see anything. That's roughly 150ms of round-trip time just for the physics — the light bouncing between continents.

At 10,000 users spread around the world, this adds up fast. Some users see your app in 100ms. Others wait 2 seconds just for the static files to arrive.

A CDN fixes this.

## What a CDN Does

A **CDN** (Content Delivery Network) puts copies of your static files on servers around the world. When a user in Tokyo requests your logo, they get it from a CDN server in Tokyo — not from your server in Virginia.

## What Gets Cached on a CDN

CDNs cache **static assets** — files that are the same for every user and don't change often:

- JavaScript bundles (your React app)
- CSS files
- Images, fonts, icons
- Pre-rendered HTML pages (with Next.js static generation)

Your API responses — which are different for each user or change frequently — stay on your origin server. The CDN doesn't handle those.

## The Cache-Control Header

You control how the CDN caches your files with the `Cache-Control` response header:

```
Cache-Control: public, max-age=31536000, immutable
```

This tells the CDN: "cache this for one year, it will never change."

For files with hash-based names (like `bundle.a3f2e1.js` — which Next.js generates automatically), this is completely safe. When the content changes, the filename hash changes, so users always get the new file.

For your HTML pages (which reference the latest bundle hashes):

```
Cache-Control: public, max-age=0, must-revalidate
```

This says: "always check if there's a new version before using the cached one."

## You Probably Already Have a CDN

If you're on Vercel, congratulations — your static assets are already distributed to their global edge network. You get CDN behavior for free.

If you're on Railway or Render, you can add Cloudflare for free. Put Cloudflare in front of your domain and your static files are automatically cached at the edge.

## What You Gain

CDN primarily reduces **latency for static assets**, which are usually most of the bytes transferred when loading a page. It also:

- Reduces load on your origin server (the CDN serves most requests)
- Handles traffic spikes gracefully (the CDN absorbs the load)
- Improves reliability (if your origin is briefly down, cached pages still load)

It's one of the highest-impact, lowest-effort improvements you can make.
