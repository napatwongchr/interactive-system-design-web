Your app has been live for a week. Your 10 friends are using it. Everything worked fine when it was just you — but now Alice wants to see Bob's posts, Bob wants to update his profile, and you want to add a mobile app later.

How does data move around without everything turning into spaghetti?

That's what an API solves.

## A Structured Contract

An **API** (Application Programming Interface) is a formal agreement between two pieces of software about how they'll talk to each other.

Without an API, your frontend would need to know exactly how your database is structured — every table, every column. Change the database and your whole UI breaks.

With an API, the frontend only knows one thing: "send a request to `/api/posts`, get back a list of posts." The database can change completely behind the scenes.

## The Restaurant Analogy

Think of it like a restaurant. You're the customer (frontend). The kitchen is the database. The waiter — the one who takes your order, goes to the kitchen, and brings back food — is the API.

You never walk into the kitchen. You don't need to know how they cook. You just read the menu (the API contract) and order.

## REST: The Default Style

Most vibe-coded apps use **REST** — each URL is a resource, and the HTTP method tells the API what to do with it:

| Method | URL | What it does |
|--------|-----|-------------|
| GET | `/api/posts` | Get all posts |
| GET | `/api/posts/42` | Get post #42 |
| POST | `/api/posts` | Create a new post |
| PUT | `/api/posts/42` | Update post #42 |
| DELETE | `/api/posts/42` | Delete post #42 |

When Cursor or v0 generated your app, it created these URL patterns automatically. The files in `app/api/` or `pages/api/` are your API.

## Why the Separation Matters

Right now, with 10 users, you could get away without a clean API. But at 10,000 users — or when you build a mobile app — having a clear contract between frontend and backend is what keeps you sane.

Your frontend doesn't care how the database stores data. Your mobile app uses the same API as your web app. Your backend can change its database without breaking anything.

The API is the handshake that makes all of this possible.
