Your app is throwing errors. Users are seeing broken pages. You open your logs and are greeted by a wall of red text.

The information you need is in there. You just need to know how to read it.

## Anatomy of a Log Line

Most log lines follow the same structure:

```
2024-03-15T02:41:07.812Z ERROR [api/posts] Connection timeout after 5000ms
  at QueryExecutor.execute (lib/db/query.ts:47)
  at PostRepository.findMany (lib/repos/posts.ts:23)
  at PostsHandler.list (app/api/posts/route.ts:12)
```

## Log Levels

| Level | What it means |
|-------|--------------|
| ERROR | Something broke. Needs your attention. |
| WARN | Something unexpected but the app kept running. Worth watching. |
| INFO | Normal events — a request was handled, a job ran. |
| DEBUG | Verbose detail, usually disabled in production. |

In production, you usually only see `ERROR` and `WARN`. If you're not seeing errors, your logging might not be set up right.

## Reading the Stack Trace

Stack traces are read **bottom-up**. The bottom is where the request entered your code. The top is where it crashed.

```
at PostsHandler.list (app/api/posts/route.ts:12)     ← request entered here
at PostRepository.findMany (lib/repos/posts.ts:23)   ← called this
at QueryExecutor.execute (lib/db/query.ts:47)        ← which called this
                                                      ← which blew up here ↑
```

Find the first line that's in **your code** (not in `node_modules`). That's your entry point for investigation. Then read up to find the actual crash site.

## The Most Common Error Messages

These appear constantly. Memorize them:

**`ECONNREFUSED`** — your code tried to connect to something (the database, Redis, an API) and got refused. The service isn't running or isn't reachable. Check: is your database up? Is the `DATABASE_URL` correct?

**`ETIMEDOUT`** — a connection or query took too long and gave up. The service is reachable but slow. Check: is your database overloaded? Is there a slow query?

**`Cannot read properties of undefined`** — your code assumed an object had a value and it didn't. You expected `user.profile.name` but `profile` was `null`. Check: is the data you're assuming exists actually there?

**`relation does not exist`** — you're querying a table that doesn't exist in the database. A migration didn't run. Check: `npm run db:migrate` or equivalent.

## The Practical Workflow

1. Find the first `ERROR` after things started breaking
2. Read the message — it's usually telling you exactly what happened
3. Find the first line of your own code in the stack trace
4. Look at that line — add a `console.log` before it if you need to see the values
5. Fix the issue

Logs are your best friend at 3am when your app is down. Learning to read them quickly is one of the most valuable debugging skills you can have.
