When you vibe-coded your app, you probably didn't sit down and think "I'll build a frontend, a backend, and a database." You just started building. But the AI did think about it — because every app, no matter how it was built, follows this same structure.

Your app has three layers.

**Frontend** is everything your user sees and touches. It runs in the browser — HTML, CSS, and JavaScript rendering the interface. Your React or Next.js components live here. The frontend never talks directly to the database. It only talks to the backend.

**Backend** is where decisions happen. It runs on a server (or a serverless function). It receives requests from the frontend, checks if they're valid, applies your app's rules, and reads or writes data. The backend is the gatekeeper.

**Database** is where data lives permanently. Turn off the server and the database still holds everything. The backend reads from it and writes to it using queries — but users never talk to it directly.

## Why Three Separate Layers?

You could technically put everything in one place. Some very simple apps do. But separating the layers gives you three big wins:

**Security.** Your database is never exposed to the internet. Only your backend can reach it. That's why you don't put your database password in your frontend code (if you've done this — change it now, seriously).

**Independence.** Each layer can change without breaking the others. You can rebuild your entire React frontend and the backend doesn't care. You can swap your Postgres database for something else and the frontend never notices.

**Scale.** Layers that get overloaded can be scaled separately. If your backend is struggling, you add more backend servers. You don't have to scale the database at the same time.

## What the AI Built for You

When you used Cursor or v0 or Claude to build your app, it generated this structure automatically. The names might vary, but the pattern is always the same:

- **A React app** (frontend) — renders your UI in the browser
- **API routes or an Express server** (backend) — handles `/api/*` requests
- **A Postgres, SQLite, or Firebase database** (database) — stores your data

Even if your whole app is in one Next.js project, those three responsibilities are still there — just organized into different folders. The three layers are a logical separation, not always a physical one.
