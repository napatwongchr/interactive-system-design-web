Two of your friends click "Save" at exactly the same time. Alice is updating her profile. Bob is creating a new post.

Your server gets two requests simultaneously. One server. Two clients. What happens?

## One Server, Many Clients

A **client** is anything that sends requests — a browser tab, a mobile app, another service. A **server** is the program that listens for requests and responds.

The key insight: one server handles thousands of clients. Not by cloning itself, but by processing requests very quickly and moving on.

## Shared State Is a Feature (and a Bug)

Because all clients hit the same server and the same database, they see the same data.

When Alice updates her username, Bob's next page load shows the new name. That's the feature — a shared, consistent world.

But it's also a source of bugs. Two users updating the same record at the same time can produce unexpected results. Your database handles this with **transactions** — a way of saying "these changes must all succeed or all fail together."

## HTTP Is Stateless (But Your App Isn't)

Here's a quirk of HTTP: every request is independent. The server doesn't remember the previous request from the same client.

Request 1: "Give me the homepage."  
Request 2: "Give me my profile."

To the server, those could be from completely different people. It has no memory.

So how does your app know who's logged in? It uses one of three tricks:

- **Session cookies** — the server gives the browser a token, the browser sends it back on every request
- **JWTs** (JSON Web Tokens) — a cryptographically signed token that proves who you are, sent in every request header
- **Database sessions** — the token maps to a row in a sessions table

The AI probably picked one of these for you. If your app has `NEXTAUTH_SECRET` or `SESSION_SECRET` in its environment variables, that's the signing key for your session tokens.

## Why This Matters at 10 Users

Ten users feels small. But it's the first time you're sharing a server. This is when you discover:

- Your database password is in your git history (fix this in the next lesson)
- Two users can race to claim the same username (you need a `UNIQUE` constraint)
- Your session tokens aren't set up correctly and users get logged out randomly

These are solvable problems. Understanding the client-server model is the first step.
