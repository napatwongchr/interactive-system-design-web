Your friend texts you at 11pm: "Hey, why is your database password in plain text on GitHub?"

You check your repo. There it is: `DATABASE_URL=postgres://admin:my_super_secret_pass@db.example.com/myapp` committed in `config.js`, visible to the entire world.

This is the environment variable problem. Here's how to fix it — and make sure it never happens again.

## The Problem: Secrets in Code

Your app needs secrets to run:
- A database password to connect to Postgres
- A secret key to sign session cookies  
- An API key to send emails with Resend
- An OpenAI key to power your AI features

You can't hardcode them — anyone who sees your code has your credentials. You can't commit a config file — your git history is forever.

You need a place to store secrets that's separate from your code.

## The Solution: Environment Variables

Environment variables are key-value pairs that live outside your code, set on the server at runtime.

## The .env File

Locally, you store your secrets in a `.env` file at the root of your project:

```bash
DATABASE_URL=postgres://user:password@localhost:5432/mydb
NEXTAUTH_SECRET=some-random-string-32-chars-long
OPENAI_API_KEY=sk-proj-...
```

Your code reads them like this:

```typescript
const dbUrl = process.env.DATABASE_URL
```

**Critical rule: Add `.env` to your `.gitignore` right now.** This file never gets committed. Each developer and each deployment environment has their own copy.

## In Production

When you deploy to Vercel, Railway, or Render, you don't use a `.env` file. You set environment variables in the platform's dashboard. They're injected into your server's environment when it starts up.

The code doesn't change — `process.env.DATABASE_URL` works the same way everywhere. Only where the values come from changes.

## Next.js Specifics

Next.js has one extra rule: variables available to the **browser** must start with `NEXT_PUBLIC_`.

```bash
NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=pk_live_...   # Browser can read this
STRIPE_SECRET_KEY=sk_live_...                    # Server only — never sent to browser
```

If you don't add `NEXT_PUBLIC_`, the variable is `undefined` in your React components. That's the security feature — your secrets stay on the server.

## The Cleanup

If you've already committed secrets, you need to:
1. Rotate all exposed credentials immediately (change the passwords)
2. Add `.env` to `.gitignore`
3. Use `git filter-branch` or BFG Repo Cleaner to remove them from history

The rotation is the important part. Removing from history is important too, but an exposed secret should be treated as compromised whether or not you clean the history.
