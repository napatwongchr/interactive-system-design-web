Your single server is maxed out. You need more capacity.

You open your cloud provider's console. Two options stare back at you: upgrade to a bigger machine, or add more machines.

These are the two fundamental ways to scale. Each has a different cost, a different ceiling, and a different set of problems.

## Vertical Scaling: Scale Up

Upgrade your existing server to a more powerful one. More CPU cores. More RAM. Faster disks.

**What's good:** Zero code changes. Works immediately. No new infrastructure to manage. Your app doesn't need to know anything is different.

**What's bad:** Expensive at the top end. Still one machine — if it dies, your app is down. Every server has a hard ceiling — you can only buy so much hardware.

Most apps start here. It's often the right answer until you hit the ceiling.

## Horizontal Scaling: Scale Out

**What's good:** No ceiling — add as many servers as you need. Redundancy — one server dying doesn't take down the app. Cost-effective at scale — many small machines are cheaper than one giant one.

**What's bad:** More complex to manage. Your servers must be **stateless** (more on this in the next lesson). Requires a load balancer. Introduces distributed systems problems.

## The Practical Reality

Most apps scale vertically until it hurts, then move to horizontal.

The crossover point depends on your workload, but it's typically somewhere between 10,000 and 100,000 users. Before that, the complexity of horizontal scaling isn't worth the trouble.

## What Makes Horizontal Scaling Hard

**Sessions** — if a user logs in on Server 1, Server 2 doesn't know about their session. Fix: store sessions in Redis, not in server memory.

**File uploads** — a file uploaded to Server 1 can't be served by Server 2. Fix: store files in S3 or equivalent object storage.

**Cron jobs** — if you have a scheduled job that runs on each server, it runs 3× with 3 servers. Fix: use a proper job queue with a single worker.

**In-memory caches** — each server has its own cache, they can diverge. Fix: use Redis as a shared cache.

These aren't dealbreakers — they're solvable. But they require thought. The next lesson covers how to design your servers so horizontal scaling becomes trivial.
